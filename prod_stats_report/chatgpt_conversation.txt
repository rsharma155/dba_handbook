For a production-grade DBA assessment, I'd actually recommend not using a WHILE loop to iterate through databases.

Instead, iterate using sp_executesql against a list of online user databases. This is how Microsoft and most experienced SQL Server DBAs approach server-wide metadata collection because:

Catalog views (sys.indexes, sys.index_columns, etc.) are metadata-only and lightweight.
No table scans occur.
No user data is read.
No locks are taken on application tables.
Dynamic SQL is simpler and faster than switching database context repeatedly.

That said, if your standard requires a WHILE loop, that's perfectly fine. I would implement it that way.
